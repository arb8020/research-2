# chapter 1 slice: design (2026-10-09, session 2)

Goal: the chapter 1 page, live on Modal, where a reader edits `gpt2.py` region by region and Run checks that
region's ops. Clean up the machinery on the way (no separate compression pass first).

Branch `engine/ch01` (worktree `worktrees/engine-ch01`) = `blogs/engine` + `engine/ch01-forward` +
`engine/ch01-harness` + `blogs/workspace-cells` + `blogs/verify-skill` (all merged clean).

## decisions

| topic | decision |
|---|---|
| cells | several cells over ONE `gpt2.py`; everything editable; `# region: <name>` / `# endregion` markers are for scroll + highlight only. A broken marker only hurts navigation |
| editor | one CodeMirror per cell, all views of one shared doc per file (CM6 split-view pattern); undo is per file |
| cell -> check | manifest `checks/ch01.json`: cell -> {file, region, ops, cmd}. Run = that cmd. Checks pick ops by name, never by text range |
| check scope | the file exactly as in the editor (whole file); only that cell's ops run. Import failure = `blocked` with file:line (+ region), not an op failure |
| commit | on pass: commit the whole file as checked, tag `pass/ch01/<cell>`, bundle -> Volume |
| check shape | general check core: run(cmd) -> immutable Run (structured outputs + fingerprints); grade(run, grader) -> Grade; report. Instantiations: numerics (ch01) and the ch00 toy (C++ trace diff) |
| expected | computed by a trusted reference run, cached. Key = fp(reference code) + case + env. fp64 truth on the candidate's device |
| matrix | case = (op, shape, dtype), swept in a run; env = (chip, toolchain, versions), one per run. Capability table per chip; a dtype the chip can't honestly test (bf16 on T4/sm_75) is a VISIBLE SKIP, the cell can still pass |
| gates | fp32: allclose per op (see tolerances) AND per-position KL max < 1e-7 (model level). bf16/fp16: loose allclose per op; model KL max < ~0.1 + logprob smoke. Token-level checks are smoke only. Long, non-repetitive prompts. (Was: 2x fp64 budget; replaced 2026-10-09) |
| where | Modal from the start: relay on `box/lease@42c05b12` with `--image blogs/engine/kernel.Dockerfile --volume /ws=blogs-ws`. Local fallback later only if needed |
| image | ONE pinned image for all chapters (py>=3.12, torch that still supports sm_75, transformers 5.x, jaxtyping, coverage, git + C/C++ toolchain). ENV BLOGS_WS_PERSIST, HF_HOME on the Volume. Heterogeneous backends deferred |
| trust | threat A: only the candidate file is untrusted. Parent runs as root; the child that imports the reader's code drops to an unprivileged user; `_blogs/` and the Volume are root-owned, read-only to the child. Trusted code is uploaded to `_blogs/` and verified by sha256 manifest before every check; that hash is also the grader fingerprint. Scratch cells (root) are threat B: later |
| names | `ws.py` -> `workspace.py` |
| ch01 content | regions roughly linear, gelu, layer_norm, attention, block/mlp, forward, generate; weight loading / config / tokenizer GIVEN. Exact list settled while writing prose |
| cell order | any order, no gating. Each cell = command + expected -> correct or the error. Stubs raise `NotImplementedError("<fn>: write this in the <region> cell")` |
| connect | the reader clicks Connect (no auto-connect: it bills). Prose near the top says to connect early: the first connect builds the image (~3 min) |
| notation | scaling-book letters for the whole series: B batch, T query len, S kv len, D d_model, F mlp hidden, N query heads, K kv heads, H head dim, G = N/K, L layers, V vocab. Sharding later: `D_X` / `{U_X}` (scaling book) ~ shardlib `/tp`, `{tp}` |
| einsum | `einops.einsum` directly in ch01, spelled `"T D, D N H -> T N H"`; the given `load()` reshapes fused GPT-2 weights into named layouts (c_attn -> D 3 N H, c_proj -> N H D). A shape-checked / sharded wrapper (seqax `einsum_unreduced` style, same spelling + `/X`) arrives with multi-rank. einops goes in the image |
| reference | per-cell "show reference" toggle: read-only view of that region's solution. The build's "solution never on the page" assert relaxes to "only inside the toggle". No hints yet |
| check core | package `blogs/assay` (our smevals): `assay/core.py` + `assay/cli.py`, instantiations `assay/ch01/`, ch00 toy. Pre-warmed child: a root process with torch/transformers imported (never CUDA) forks per check; the fork drops to nobody before importing the candidate |
| layout rule | fewer files: split a file only near ~1k lines |
| shapes | shape suffixes on every tensor in reference, starter signatures and given code (`x_TD`, `w_q_DNH`). Chapter 1 is `TD` (one sequence, no batch); the engine's packed batch is also `T` (all tokens in a step). Reductions via `einops.reduce`; softmax keeps `dim=-1` with the suffix naming the axis |
| reader code width | 80 columns for code readers see (ref/chNN); editors soft-wrap so nothing scrolls sideways |
| tolerances | **chapters 0/1: simple, decided 2026-10-09 ("don't bikeshed correctness; land today").** Per op: allclose vs fp64 truth, pass iff max(\|C-T\| - (atol + rtol\|T\|)) <= 0, one (atol, rtol) per dtype (`TOL` in `assay/ch01/suite.py`: fp32 1.5e-4/1e-5, fp16 2e-2/2e-2, bf16 0.15/0.15, picked from self-test data; low precision catches gross bugs only, exact GELU is an expected miss there). Row metric: worst \|C-T\|/(atol+rtol\|T\|). Op inputs: centered and offset (mean 3, std 0.5). Model level: fp32 per-position KL max < 1e-7 + top-k smoke; bf16 KL < 0.1. **Deferred to the kernel chapters (the principled design, kept):** model level: per-position KL < 1e-7 only (KL ~ 1/2 Var_p(logit error)). Contractions: BLAS-style per-element ratio \|C-T\| / (u(\|A\|\|B\|) + u\|T\|), hard limit k, warn c*sqrt(k). Composite ops: Monte Carlo arithmetic on the fp64 reference, framed as a one-sided test with alpha (false-fail), beta and theta (min detectable bug), as in TRT-LLM's accuracy tests. Inputs offset from zero at several magnitudes. Old 2x rule kept as a reported metric for one chapter |
| check config | **chapters 0/1: constants in `assay/ch01/suite.py` (`TOL`, `KL_MAX`) and the `@op(dims=..., dtypes=...)` declarations in `ops.py`; no TOML.** Regrading without re-running still works (runs store an error frontier any tolerance can grade). **Deferred to the kernel chapters:** split by what it invalidates. WHAT TO RUN (re-runs): `@op(sizes={"T": ..., "D": ...}, dtypes=..., kind=...)` on the reference; dims come from the shape suffixes of its parameters. HOW TO JUDGE (regrade only): `checks/chNN.toml`, smevals-shaped: `[grader.<kind>] checks = [ {check = "<name>", ...params} ]` ordered, plus `[op.<name>]` overrides (grader, blocking). Kinds: contraction, elementwise, composite, model. The safety checks (returned, dtype_shape, inputs_unchanged, deterministic) are fixed in core, always first, not configurable. TOML holds plain numbers, no formula strings; formulas live in the check code. The TOML (with short comments) is the reference; no generated doc |
| tolerance docs | one hand-written explanation page, `blogs/engine/correctness.md` ("How assay decides an implementation is correct"), linked from ch01 as an optional read. No reference doc: the TOML and the check functions' docstrings are the reference. Code comments link to the explanation |
| TS lint | oxlint replaces ESLint (type-aware port) + 4 vendored anti-slop guards (no-unsafe-dictionary-type, no-chained-type-assertions, no-conditional-empty-object-spread, no-widen-then-assert); catch params named `cause`. Canonical config in ~/dotfiles/lint/. A schema library for boundary parsing is a separate, later decision |

## contracts between pieces

**check command** (what a cell's cmd runs; also runnable by hand, no page or server):
```
run_checks <chapter> [--op NAME]... [--dtype D]...    # cwd = the tree being checked
stdout: JSON lines
  {"kind":"log","text":...}                                            free-form progress
  {"kind":"verdict","op","case","dtype","chip","outcome":"pass|fail|skip|blocked",
   "score"?, "metrics":{}, "notes":"", "where"?:{"file","line","region"?}}
  {"kind":"summary","outcome":"pass|fail|blocked","counts":{...},"run":"<run id>"}
exit: 0 pass, 1 fail or blocked (real evidence), 2 infrastructure error (never graded, smevals-style)
```

**manifest** `checks/chNN.json` (in the reader's repo, read by workspace.py and the page):
```
{"chapter":"ch01","cells":[{"name":"attention","file":"gpt2.py","region":"attention",
  "ops":["causal_attention"],"cmd":["run_checks","ch01","--op","causal_attention"]}, ...]}
```

**trusted code** `_blogs/` in the sandbox: `workspace.py`, the check core + instantiations, specs/references,
`MANIFEST.sha256`. Uploaded by the page on Connect; workspace.py verifies hashes before each check.
