## A. Kernels layout: one op = one file

1. `kelpie_models/kernels/ops/<op>.py` for every kelpie op (rms_norm, layer_norm, gelu, silu_mul, rope, paged_attention, sample, clamped_swiglu, chunk_gated_delta_rule, causal_conv1d, mla_attention, dsa_indexer_topk, compressed_kv_attention, grouped_mm_mxfp4, ...). Each file holds, in this order: the contract (`@op` on a plain torch function: typed signature + docstring with the math + reference body), `fake` (shape rule), `sample_args` (small tensors for opcheck/compare), `backward` = `register_autograd` whose body raises `NotImplementedError("backward: training deferred (branch integrate/train-step)")`, then every backend's adapter for THIS op: `@<op>.register("fla", source="fla.modules.layernorm.rms_norm", predicate=...)` with the backend's quirks (unsupported args as `Literal[None]`, alignment predicates) next to the signature they bend. Nothing about an op exists outside its file.
2. Every op is `kelpie::*`. NEVER `register_kernel` on `aten::*` — overriding torch's own op is process-global and leaks into any other torch code in the process (an HF oracle, a trainer). Ops torch already has (`layer_norm`, `rms_norm`, `gelu`, `silu`) become `kelpie::layer_norm` etc. whose reference body calls `F.*`. Models call `torch.ops.kelpie.<op>` for every op we define; `F.*` directly only for ops we do not define.
3. `kelpie_models/kernels/__init__.py`: `declare_backend(name, package=, min_version=, max_version=, extra=)` once per backend (triton, fla, liger, flashinfer, flash_attn, metal, pallas, nki); lazy import at first bind; missing or out-of-range -> `BackendUnavailableError("<impl> needs <package>; install kelpie[<extra>]")`. Selecting an impl never silently falls back.
4. Registry derived, never hand-kept: `ops/__init__.py` imports every `ops/*.py`; a conventions check (in `scripts/test`) asserts every op file is imported, every op has fake + sample_args + backward, every adapter names a declared backend. Delete `ops.py`'s `KELPIE_OPS/ATEN_OPS/_OP_HANDLES/_OPCHECK_ARGS` tables; `ops.py` shrinks to machinery: `op`, `Op.register`, `bind`, `bound()`. Delete `kernels/adapters/*.py` (their content moves into the op files) and `kernels/devices/*/IMPLS` (a device's defaults become `DEFAULTS = {"cuda": {"rms_norm": "fla", "paged_attention": "flashinfer", ...}}` in `kernels/devices.py`, keyed by op name and impl name — one small table, the only place device defaults exist).
5. User override spelling, keyed by the op object, resolved once in `build()`:
   ```python
   serve(gpt2, device="cuda", kernels={ops.rms_norm: my_rms_norm, ops.paged_attention: ops.paged_attention.reference})
   ```
   `kernels=` values are callables (any function with the op's signature) or an impl name string registered on that op (`"fla"`). `build()` logs one line: `kernels[cuda]: rms_norm=fla rope=triton paged_attention=reference ...`. `examples/main.py` uses this spelling and the two `# review:` marks are resolved (delete them).
6. `fingerprint(op, impl)`: normalized-AST hash of the adapter + reference source + the backend's installed version (popcorn `core/fingerprint.py` as the reference; ~100 lines, ours).

## B. `kelpie build`: no runtime JIT, cache + manifest, fail closed

7. `build(model, *, device, dtype, kernels, capture, cache: Path, allow_build=False)`: for every bound op and every bucket shape in the ladder (`Buckets`), warm/compile into `cache/triton` (`TRITON_CACHE_DIR`), FlashInfer `build_jit_specs` into `cache/flashinfer`, CUDA graphs per `ProgramKey`; run `bench.compare(op, impl, shape)` against the fp64 reference; time it; write `cache/manifest.json`: `{program_key, ops: {name: {impl, fingerprint, verdict, err, budget, time_us}}, toolchain: {torch, triton, cuda, zig}, built_at}`.
8. `serve --cache X` (allow_build=False): open manifest; for every bound op assert entry exists ("not built: run kelpie build"), fingerprint equal ("kernel source or backend version changed since build"), verdict pass ("incorrect kernel at build time"); mark cache dir read-only; install a Triton compile hook (`triton.knobs`/`JITFunction.cache_hook`) that raises `RuntimeError("JIT at serve time: <kernel> <shape> not in cache")`; `FLASHINFER_DISABLE_JIT=1`. Nothing on the filesystem is trusted without the manifest.
9. `build` diffs timings against the previous manifest in the same cache dir and warns at >10% regression per op/shape (`logging.warning`, never fails).
10. `torch.compile` opt-in: `build(compile=True)` wraps the forward; custom ops stay opaque to inductor; not default; record `compile` in `ProgramKey`.

## E. Attention seam rulings (user, 2026-09-10) — least abstraction

- Plan metadata: ONE canonical form from Zig (dense block_table[R,P], seq_lens, query_start_loc, slot_mapping, kinds, row_request). Adapters derive what their backend wants (FlashInfer CSR: indptr/indices/last_page_len) inside the adapter. No backend-shaped fields in the plan until a real adapter measures the conversion cost; then it is an appended field.
- KV layout: stated by the op contract, once, in `ops/paged_attention.py`: K and V are two members, each `[pages, block, Hkv, D]`. Fix the reference body to read that (today it interleaves K/V rows by accident: `flat[:, 0::2]`). `groups.py:kv_spec` and `sdk/kv.py` allocate accordingly. Adapters read it or refuse via `predicate`. No bind-time layout property.
- Call site: flat op, no `attention()` wrapper. `layer_caches[i] -> (group, member)` resolved at build; the author indexes `kv[g][m]`, `requests.block_tables[g]`, `requests.slot_mapping[g]` directly.
- Attention is a family of ops (paged_attention, mla_attention, compressed_kv_attention, chunk_gated_delta_rule) sharing the plan tensors, not one signature.

## F. Rulings 2026-09-10 (session 6) — these override anything above they touch

- `build(..., check: bool = False, bench: bool = False)`: correctness and timing are two plain bools, default off. `serve --cache` requires an entry + matching fingerprint for every bound op; a missing verdict (built without `check`) is a `logging.warning`, not a refusal; a recorded FAIL verdict refuses.
- Cache is per op: `manifest.json` `ops[name]` entries are keyed by `(impl, fingerprint, shape)`; `build` reuses an entry whose fingerprint matches and rebuilds only the ops whose fingerprint changed. `program_key` is recorded but is not the cache key.
- Every serve goes through `build`, including all-reference (`kernels={op: op.reference ...}`); reference impls get manifest entries like any other (fingerprint of the reference body, verdict trivially pass when `check`).
