# observe — design contract

Wide events are the storage primitive. OTLP's three signals are the vocabulary.
One JSONL file per run. Every line is one event. Dashboards are projections.

## On disk

Every line has: `ts` (float unix s), `kind`, plus `static_fields` (stamped on every
line by `setup_logging`: `run_id`, `run_name`, `git_sha`, `git_dirty`). `static_fields`
are **attrs**, not fixed fields: a reader lifts only the fields listed below and folds
everything else — static fields included — into `attrs`.

```
kind: "log"     {ts, kind, level, event, logger, ...attrs}
kind: "span"    {ts, kind, span_name, trace_id, span_id, parent_span_id, start_time_unix_nano,
                 end_time_unix_nano, duration_ms, status: "ok"|"error", error?, error_type?, ...attrs}
kind: "metric"  {ts, kind, name, value, ...attrs}        # one gauge data point, point-shaped
kind: "artifact" {ts, kind, name, mime, payload, ...attrs}  # one named, typed structure
```

The field sets are **exact per kind**. `level`, `event` and `logger` belong to
`kind: "log"` ONLY; a metric or span line carrying them is a contract violation.
`parent_span_id` is **always present** on a span: JSON `null` means "root span"
(the key is never omitted). `error`/`error_type` appear only when `status == "error"`.
`payload` is a nested JSON value, not a string. See "Artifacts" below.
`observe/log.py::JsonlFormatter.format` is the single place that knows these sets, and
`observe/dashboard/src/core/__fixtures__/golden.jsonl` (generated by
`observe/scripts/golden.py`) is the committed cross-language pin.

`kind` is always present and explicit. A reader that sees an unknown `kind` or a missing
required field must fail loudly (throw / raise), never skip.

`step` is NOT first-class. It is an attr like any other. The viewer picks the x-axis.
Config is a `log` event named `run_start` with the resolved config flattened as attrs.
`run_end` is a `log` event.

## Artifacts

A metric is a number; an **artifact** is a structure a purpose-built renderer draws —
a trajectory, an attention map, a config tree. `mime` is the renderer's selector: a
renderer that does not recognise a mime must leave the artifact alone rather than
guess at its shape, and must say so on screen rather than drop it silently.

- `payload` is **inline JSON only**, bounded: `artifact()` serializes once and asserts
  the result is ≤ 1 MiB (`observe/_artifact.py::MAX_PAYLOAD_BYTES`). A JSONL line is
  read whole by every consumer (the tailer, DuckDB, `jq`), so an unbounded payload is
  an unbounded line. **File-backed artifacts (a PNG, a checkpoint) are deferred** — no
  `uri` field exists yet, and adding one is a contract change, not an extension.
- `step` is an attr like everywhere else, never a fixed field.
- A payload that `json.dumps` refuses is a **crash at the call site**, not a `str()`
  fallback. The formatter's `default=str` can never reach a payload for this reason.
- **The dashboard does not type payloads.** `Artifact.payload` is `unknown` in
  `core/events.ts`; a renderer parses it at its own boundary and reports its own
  shape errors. Core knowing what a trajectory is would make every new artifact
  type a core change.

### Trajectory payload — `application/x-trajectory+json`

```
{env: string, obs: number[][], actions: number[], rewards: number[]}
```

One episode, column-oriented. `len(obs) == len(actions) + 1 == len(rewards) + 1`:
**`obs` carries the terminal observation**, so `obs[t]` is the state the agent saw
when it chose `actions[t]`, and the renderer can still draw the frame the episode
ended on — for CartPole that is the pole-fell frame, the one a human actually wants
to see. Lengths are asserted by the parser, not assumed.

`env` is the Gymnasium env id. A renderer that has no surface for that env renders a
loud "no renderer for <env>" state with the raw obs shape — never a blank panel.

## Python API (observe/)

```python
setup_logging(log_file=..., static_fields={...})  # existing
log.info("event_name", extra={...})  # log — stdlib, formatter stamps kind="log"
with span("name", attributes={...}) as s:
    ...  # span — timing + status only, no results
metric("name", value, **attrs)  # metric — one point
metrics({"a": 1.0, "b": 2.0}, **attrs)  # sugar → N metric points, same ts/attrs
artifact("name", payload, mime="application/x-...+json", **attrs)  # artifact — one structure
```

Python is a **producer only**: it appends lines to `runs/<name>.jsonl` and nothing else.
Serving is TypeScript (below); a training script never opens a socket.

Spans carry context needed to debug *that span* (step, batch_size). Results go in `metric`.

**Span nesting is implicit.** A `ContextVar` holds the innermost open span; a span opened
with neither `parent=` nor `trace_id=` becomes its child (same `trace_id`,
`parent_span_id` = enclosing `span_id`). The var is reset on exit, exception included.
`parent=` wins; `trace_id=` alone starts a root in that trace. `s.context` is the span's
`SpanContext`, for handing across a boundary the var does not cross: a `threading.Thread`
target starts with an empty context, so a span there is a new root unless it gets
`parent=s.context` or runs under `contextvars.copy_context().run`. (asyncio tasks copy the
context, so they nest.)

**Console is lossy, JSONL is not.** The console formatter drops `kind`, span ids and the
raw nanos (`ConsoleFormatter` / `CONSOLE_HIDDEN`); a span prints as name +
`duration_ms` + `status` + attrs. Anything that needs identity reads the JSONL.

## Dashboard (observe/dashboard/, Vite + React + TS strict)

```
server/     Bun.serve — stateless, pull-based. store.ts is the ONLY module that knows
            the store is a directory of JSONL files; swap it to move the store.
              GET /runs              -> index, each run's first line only
              GET /runs/<f>.jsonl    -> Range: bytes=N- -> 206 suffix; EOF -> 416
              GET /*                 -> dist/ ("/" -> index.html; no dist -> 503 + hint)
core/       tail (byte cursor, Range) → parse(line) → Event = Log | Span | Metric | Artifact → raw table
views/*/    discovered via import.meta.glob('./views/*/view.ts'); core never imports views
```

View contract (the only shared interface):

```ts
export const view: View = {
  name: string,
  accepts: Kind[],                          // which kinds it receives
  mount(el: HTMLElement): State,            // once
  append(state: State, events: Event[]): void,  // only new events, already filtered by accepts
}
```

Two shapes of UI code:
- **components** (React): chrome, layout, run picker, filters, raw table. Cheap to re-render.
- **surfaces** (imperative, behind a ref): the streaming hot path inside a view. Own their
  DOM. Never put the point array in React state.

Core owns layout: one column, one slot per view, in discovery order. Views don't know
each other exist.

Pure functions (parse, toSeries, ema, downsample) have no React/DOM imports.

## Rules from ~/dotfiles/docs that bind here

- parse at the boundary into honest types; trust internal types
- sum types with visible switch; exhaustiveness via `never`
- no semantic fallbacks: unknown kind → throw
- no bare `as`; validate then narrow
- core/ → views/ import is forbidden (lint-enforced); server/ → app/, views/ likewise
- earned compression: no second abstraction until a second instance exists
- 0.1s feels instant; nothing on the poll path may exceed that

## Deferred (deliberately)

instruments, run registry, obol theme system (CSS variables only for now).

## Panels (target shape, decided 2026-09-17)

A **panel** is a query that feeds a viz. This is Grafana's panel with Vega-Lite as the
viz grammar — not an abstraction we invented.

```
Panel = { query: SQL, viz: VegaLiteSpec }      # rows from the store → marks on screen
```

- **Query**: DuckDB, server-side (`GET /query?sql=`), over `runs/*.jsonl` (all runs).
  The store owner does the querying; the browser gets rows. Row cap + timeout, always;
  a capped result is returned *with* a `truncated` flag, never silently cut.
- **Viz**: Vega-Lite spec. Written in TS/JSON today; Altair emits the same JSON from
  Python later (that is the Python-authoring path — a spec, never pixels).
- **Failure is per panel, loud, in place** (a notebook cell with a traceback):
  ```
  PanelState = ok{rows, view} | query-error{message} | shape-error{field, expected, got}
             | truncated{rows, limit}
  ```
  Rows are checked against the spec's encodings *before* rendering — Vega-Lite draws an
  empty chart on a missing field, which is a semantic fallback, so we don't let it.
- Live = re-run the query on an interval; the tailer stays the live path for raw events.

Judo: once Vega-Lite renders panels, the hand-rolled `views/metrics/chart.ts` must be
deleted, not kept beside it. The metrics view becomes default panels
(one per metric name, `x: step`).

## Register (decided 2026-09-17)

Figure, not console. The dashboard is a HUD: it shows what the player needs and hides
the rest behind hover / click / drawer.

- **Landing surface = metric panels only.** Status pill and run picker are chrome.
- **Logs** live in a slide-in drawer (two views over `Log`: streaming terminal-style,
  and dataframe-style with selection). Never on the landing surface.
- **Warnings/errors** (`level ≥ WARNING`, parse errors, panel errors) surface as toasts.
- **Spans** get their own view (lanes by `span_name`, blocks start→end, shared x — the
  humans& "RL Training Simulator" figure) for drilling into perf.
- **Skin**: obol's `paper` (`obol/cli/sessions/viewer/src/styles.css`) — warm canvas
  `#f5f5f1`, ink `#252825`, hairlines not boxes, Inter + DM Mono. Dark only where it
  helps temporal reading (span lanes), if at all. Vega-Lite gets a theme config from the
  same tokens.
- **Enforcement test** (from obol's visual spec): any new element on the landing surface
  must name which of {metric panel, status, run picker} it is. If it can't, it's a
  drawer, a toast, or a view — update this section first.

Reference: obol `docs/design/dataset-explorer-alignment.md` Q5 — "scientific developer
workbench: light/warm default, precise typography and plots... avoid looking like generic
observability software." Aurora / humans& screenshots in
`docs/design/dataset-explorer-report/screenshots/`.

### `/query` wire contract

```
GET /query?sql=<urlencoded>            (read-only; DuckDB over runs/*.jsonl)
200 { columns: [{name, type}], rows: unknown[][], truncated: boolean, limit: number, ms: number }
400 { error: string }                  # DuckDB's message verbatim (parse/bind/type error)
408 { error: string }                  # timeout (default 5000ms)
```
- `rows` is columnar-ordered arrays (row i = rows[i], value j matches columns[j]); no objects,
  so the shape check is `columns` vs the spec's encodings.
- The store is exposed as a view `events` (all runs, one column per top-level field plus `file`),
  so `SELECT step, value FROM events WHERE kind='metric' AND name='wm_loss'` works.
- **Nested `payload` needs no special handling.** `read_json_auto(..., union_by_name=true)`
  infers `payload` as a STRUCT whose fields are the UNION of every payload shape in the
  store, filling foreign keys with NULL, and widens genuinely conflicting field types to
  JSON rather than failing (measured). So `SELECT name, mime FROM events WHERE
  kind='artifact'` is exact, while `payload.<field>` is only meaningful for rows whose
  mime you also filtered on. Panels query `name`/`mime`/attrs; payloads are for renderers,
  which read them off the event stream, not out of SQL.
- Default `limit` 10000 rows, applied as `SELECT * FROM (<sql>) LIMIT limit+1`, so a full
  page and a cut one are distinguishable: `truncated` is measured, never guessed. A
  `?limit=` outside 1..1000000 is a 400, never clamped.
- Read-only is DuckDB's own parser, not a keyword blocklist: `json_serialize_sql` refuses
  anything that is not a SELECT and reports the statement count, so DML/DDL/PRAGMA/SET/
  ATTACH/COPY and multi-statement text are all 400s. `access_mode=READ_ONLY` is not
  available — DuckDB refuses it for an in-memory database.
- Timeout (default 5000ms) is `connection.interrupt()`: the query stops in the engine, not
  just in the response. One connection per query, because `interrupt()` is connection-wide
  and would otherwise cancel a concurrent request's query. The `events` view is a TEMP view
  on that connection (a shared one is a catalog write-write conflict when requests overlap).
- **Types are DuckDB type names verbatim** ("BIGINT", "DOUBLE", "DECIMAL(18,4)"). Values are
  coerced to JSON: BIGINT/HUGEINT inside ±2^53-1 -> number, outside it -> decimal *string*
  (a silently rounded step count is worse than a string the caller must notice);
  DATE/TIMESTAMP -> ISO 8601 UTC string; BLOB -> base64; DECIMAL/FLOAT/DOUBLE are already
  numbers.

   all cells now. ~40 lines.

   steps and answers at the next step boundary by emitting artifacts. Weights never
   duplicated; control never enters the hot path beyond one `stat()`.

   `runs/<name>/artifacts/`, server serves blobs. MLflow-shaped.

   file with incremental append; `/metrics` (Prometheus) as another projection off the same
   server.

   `.panel-empty` nearly unreachable (delete?); `prefers-color-scheme` block is only the
